# M7-S015 — Rapport ROI minimal consolidé (snapshot-ready M8)

> Architecte : Qwen3.7-Max (6e ADR prose). ADAPTATIONS : devise CAD (Québec) ; consolider_roi(rapport_attribution: dict, rapport_ads: dict, mapping: dict, calendrier: dict, date_reference) — les DICTS des moteurs réels (les tests appellent attribuer()/generate_report() en direct), valider_mapping sur dict ; métriques additives = DÉFINITIONS au catalogue (M8 calcule), « m7_roi_par_canal déjà déclarée » à vérifier contre le fichier réel ; hook lint datetime = test getsource (pattern établi).

## 1. Autorité et périmètre
Le module vit dans `src/roi/` et expose une consolidation purement déterministe des sorties S013 (attribution) et S014 (ads intelligence), sans jamais appeler de réseau, d'horloge, de LLM ni de modèle MMM. La date de référence ISO-8601 est fournie par l'appelant, garantissant que deux invocations à paramètres identiques produisent un snapshot byte-identique. Le module est en lecture seule sur les fixtures S013/S014 et sur le contrat UTM S012 ; il n'écrit que le rapport JSON et son digest.

## 2. Jonction canal ↔ campagne ↔ fenêtre (tranché)
Le pont est un **mapping déclaré** dans `contracts/roi-mapping.v1.yaml` épinglé par sha256, associant chaque `fenetre_id` du calendrier S008a à une liste explicite de `utm_campaign` attendues et à une `plateforme_ads` (google|facebook|instagram). Aucune inférence par substring de slug n'est autorisée, car elle produirait des faux positifs silencieux dès qu'un slug contiendrait accidentellement un identifiant de fenêtre. Si une campagne UTM remontée par S013 n'apparaît dans aucun mapping déclaré, elle est classée `sans_pont` et son coût reste `donnees_insuffisantes:raison=mapping_absent` — jamais zéro, jamais estimé. Si une fenêtre du calendrier n'a aucune campagne UTM correspondante dans les fixtures, son digest FR mentionne explicitement `aucune_campagne_liee`.

## 3. Structure du rapport ROI
Le rapport est un dict à quatre clés racines : `par_canal` (liste de `{canal, leads_derniere_touche, cout_ads, cout_par_lead|donnees_insuffisantes:{raison}}`), `par_fenetre` (liste de `{fenetre_id, digest_fr, nb_campagnes, nb_leads_attribues}`), `snapshot_id` (sha256 hex du contenu trié), `refs` (sha256 des fixtures S013, S014 et du contrat UTM S012). Le champ `cout_par_lead` n'est émis que lorsque `leads_derniere_touche > 0` ET `cout_ads` est un nombre fini ; sinon `donnees_insuffisantes` avec raison parmi `zero_leads`, `cout_indisponible`, `mapping_absent`. La division par zéro est structurellement impossible car le code refuse d'entrer dans la branche de calcul quand le dénominateur est nul.

## 4. Métriques additives m7-metrics.v1.yaml
Quatre entrées additives, toutes mensuelles, consommateur M8 : `m7_cout_par_lead_par_canal` (coût ads du canal divisé par leads dernière touche du canal, EUR/lead) ; `m7_taux_attribution` (leads attribués / leads totaux CRM sur la période, ratio) ; `m7_part_non_attribuables` (leads CRM sans visitor_id ou hors fenêtre 30 j / leads totaux, ratio) ; `m7_cout_par_lead_global` (somme des coûts ads joignables / somme des leads attribués à un canal joignable, EUR/lead). La métrique `m7_roi_par_canal` déjà déclarée reste inchangée et n'est pas recalculée ici — S015 fournit les intrants, M8 calcule le ratio final.

## 5. Interfaces publiques
`consolider_roi(chemin_rapport_attribution: str, chemin_rapport_ads: str, chemin_mapping: str, chemin_calendrier: str, date_reference: str) -> dict` : orchestration pure, retourne le rapport complet. `calculer_snapshot_id(rapport: dict) -> str` : sha256 du JSON canonique trié, reproductible. `generer_digest_fenetre(fenetre: dict, campagnes_liees: list, leads_attribues: int) -> str` : phrase FR déterministe type « Fenêtre hiver : 2 campagnes, 14 leads attribués, coût moyen 38 EUR/lead ». `valider_mapping(chemin_mapping: str) -> None` : lève sur contrat non conforme avant toute consolidation.

## 6. Anti-dérive et TDD RED
Cinq cas RED capturés avant implémentation : (a) jointure complète S013+S014 sur une fenêtre → `cout_par_lead` numérique exact ; (b) canal présent en S013 mais absent en S014 → `donnees_insuffisantes:raison=cout_indisponible` ; (c) campagne UTM hors mapping déclaré → classée `sans_pont`, jamais agrégée dans un coût canal ; (d) deux appels identiques → `snapshot_id` strictement égal, prouvé par assertion byte-à-byte ; (e) fenêtre du calendrier sans campagne liée → digest FR contenant la chaîne `aucune_campagne_liee`. Tout test qui invente un chiffre, divise par zéro ou consulte `datetime.now()` fait échouer le build via un hook de lint interdisant l'import de `datetime` hors signature explicite.
