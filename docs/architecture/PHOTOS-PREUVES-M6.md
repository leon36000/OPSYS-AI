# Photos associées aux pertes et bris M6

Lot M6.13, continuation privée de 28c467c8, 8 octobre 2026. Le raccord complet est en qualification ; ce document décrit son contrat, pas une livraison du projet. OPSYS-AI demeure PARTIEL.

La déclaration terrain conserve une note et zéro à trois références CAS par position finale de ligne PERTE/BRIS. La chaîne de preuves référence le mouvement réellement ajouté au registre principal ; deux mouvements identiques gardent deux références distinctes. Une ancienne perte sans preuve reste explicitement sans preuve. Le fichier, son empreinte et la déclaration de l'employé ne prouvent ni la scène, ni la date de prise, ni le lieu, ni la cause de la perte.

L'aperçu admin demande une sélection fermée `{wct_id,preuve:{index,hash_maillon},position_photo}` à la Gateway. La personne, le rôle et l'appareil sont dérivés du jeton DEVICE vérifié ; ils ne viennent jamais d'arguments publics. Les pages de lecture sont courantes, sans garantie de snapshot figé. L'absence de rôle, de liaison ou de fichier entraîne un refus explicite.

Le Core communique avec le moteur métier par un canal privé distinct de MCP : `OPSYS_M6_PREUVES_BRIDGE_URL` désigne le chemin fixe `/mcp/fichiers/m6-preuves`, et `OPSYS_M6_PREUVES_BRIDGE_JETON` est un credential serveur privé d'au moins 24 caractères ASCII non blancs, distinct des credentials MCP public, contexte et cron. Ces variables sont provisionnées dans l'environnement de l'instance ; aucune valeur n'est enregistrée dans Git ou dans l'app. Le canal est désactivé si le credential est absent. Son URL ne contient ni credentials, ni query, ni fragment et aucune redirection n'est suivie. Il utilise exclusivement la factory de la base canonique capturée lors de la construction de l'application ; une autre base ou un changement de credential ferme l'accès.

Le corps privé est fermé : `{selection,identite:{personne,role},appareil_id}`. Le helper métier vérifie le rôle admin SQL actuel, le WCT, l'intervention et les liens de la preuve dans une transaction fraîche. Il vérifie le CAS complet une fois. Le pont vérifie à nouveau SHA-256, MIME, taille, structure et décodage avant les en-têtes image. JPEG et PNG seulement, au plus 10 MiB, une image fixe, 8192 pixels par dimension et 16 millions de pixels. Pillow 12.3.0 est déjà verrouillé dans `requirements-runtime.lock.txt` ; aucune dépendance n'est renouvelée. Un runtime sans décodeur ferme l'aperçu. Le contrôle travaille hors de la boucle ASGI. Un délai ou une déconnexion libère la requête ASGI sans attendre le worker ; il ne préempte pas un travail synchrone déjà lancé. Deux travaux actifs au plus sont admis, sans attente : le slot reste tenu par le worker jusqu’à son retour, même après l’annulation. Une saturation ferme la lecture sans créer une permission.

Le flux privé revalide l'autorité métier avant chaque fragment d'au plus 64 KiB, sans relire le CAS. L'opération privée `/revalider`, même sélection et credential, retourne seulement les métadonnées liées et l'autorité courante, sans pixel. Le Core vérifie l'empreinte du tampon complet avant les pixels client, puis appelle cette revalidation SQL et revérifie le même DEVICE, la même attribution et la même portée avant chaque fragment client. L'absence de réponse actuelle n'accorde jamais la permission. Ce double passage ajoute des lectures SQL : aucun gain de performance ni latence terrain n'est revendiqué sans mesure.

En-têtes image : `Content-Type`, `Content-Length`, `X-Opsys-Sha256`, `ETag`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`. Avant les en-têtes, les refus sont du JSON fermé sans détail technique interne. Après les en-têtes image, le flux est interrompu ; aucun JSON d'erreur n'est injecté dans les pixels. Un retrait n'efface pas les octets déjà reçus. Le pont borne le délai de requête à 120 secondes et surveille la déconnexion avant la lecture initiale.

L'app doit télécharger dans un fichier temporaire privé, valider SHA/taille/MIME avant `Image`, puis purger lors d'un refus, changement de sélection, session, réseau ou sortie de l'écran. Aucun bearer dans une URL, aucun cache de permission, aucune déclaration de véracité d'une photo. Le raccord mobile et le parcours Gateway/SQL restent à qualifier avec leurs propres preuves ; les tests ASGI avec callbacks et les tests SQLite/CAS ne sont pas des tests de téléphone.
