# R7 — M3 Estimation & M4 Field Ops : briques open source pour exceller

Recherche vérifiée (GitHub API via `mcp__github__search_repositories`, fichiers LICENSE bruts via
`raw.githubusercontent.com`, sites officiels via WebSearch/WebFetch). Toute affirmation non
recoupée par une de ces sources est marquée **NON VÉRIFIÉ**. Date de constat : 2026-09-28.

## 0. Constat sur le code existant (lecture seule)

**M3-estimation** (`src/m3_estimation/`, 13 modules, ~2,7k LOC) : 100 % logique pure stdlib.
`hierarchie_echelle.py` et `qualite_photos.py` ne lisent **aucun pixel** — ils classifient des
métadonnées *déclarées par l'appelant* (résolution, éclairage 0-10, `reference_echelle.type`).
`monte_carlo.py` tire avec `random.Random(graine).uniform(min,max)` (10 000 tirages) — **aucune
distribution triangulaire/PERT**, un barème `{min,max}` seulement. `devis.py` assemble le contrat
`EstimationV1` — **ne génère aucun PDF**. Le registre estimé-vs-réel (`registre.py`) est prêt à
recevoir un coût réel mais rien ne l'alimente encore. Architecture constante : fail-closed,
verdicts nommés, échappatoire `INDETERMINE` obligatoire (D-032), zéro réseau/horloge/hasard non
seedé — **toute brique ajoutée doit respecter ce contrat, jamais le contourner**.

**M4-field-ops** (`src/m4_field_ops/`, 12 modules, ~2,4k LOC, 427 tests) : `cedule.py` est un tri
round-robin déterministe (ville tokenisée, type, lead_id) — **pas un VRP** (aucune distance, aucune
fenêtre optimisée, aucun coût de déplacement). `pointage.py` fait de la géo-cohérence par
Haversine pure Python contre un `referentiel_villes` fourni — **pas de GPS réel, pas de Traccar**.
Aucune météo, aucun routage réel. Le PRD (§8) repousse explicitement VRP/routage/météo/GPS réel en
GATED/T3 — c'est exactement le périmètre de cette mission R7.

### Monte Carlo / distributions

`monte_carlo.py` utilise déjà `random.Random(graine)` stdlib (bit-à-bit reproductible, testé
CA-M3-10/11) avec un seul tirage `uniform(min,max)`. Pour passer à triangulaire/PERT :

- **scipy.stats** ([scipy/scipy](https://github.com/scipy/scipy), **BSD-3-Clause** vérifié, 15 046⭐,
  push 2026-09-27) fournit `scipy.stats.triang` nativement (reparamétrage loc/scale nécessaire,
  documenté). **numpy** ([numpy/numpy](https://github.com/numpy/numpy), BSD-3-Clause — licence
  numpy.org, le détecteur GitHub renvoie "Other" par faux-négatif, 32 866⭐) pour la vectorisation.
- **PERT (beta-PERT)** : formule fermée (`α = 1 + 4(mode-min)/(max-min)`, etc.) implémentable en
  ~15 lignes sur `scipy.stats.beta` — **recommandé plutôt que** le paquet
  [tadamcz/betapert](https://github.com/tadamcz/betapert) (vérifié : **1⭐, dernier push
  2024-01-05, AUCUN fichier LICENSE détecté** → tous droits réservés par défaut, à ne PAS
  dépendre). Effort **S**, risque nul (formule mathématique, pas de dépendance tierce).
- Remplacer `random.Random.uniform` par une vraie triangulaire/PERT reste compatible avec le
  déterminisme bit-à-bit déjà prouvé : `random.Random(graine).triangular(low, high, mode)` existe
  **dans la stdlib** (module `random`, déjà importé) — le plus proche du principe « stdlib
  d'abord » du projet, sans même ajouter scipy en dépendance dure pour ce seul besoin.

## 3. Capacités à donner aux agents (outils / skills / politiques)

### Agent(s) M3 — Estimation
- **Outil `mesurer_surface_photo`** : pipeline SAM2 (masque) + Grounding DINO (localisation par
  texte de la référence et de la cible) + géométrie sténopé → renvoie une mesure ET une confiance,
  jamais un chiffre nu. Le résultat alimente `hierarchie_echelle.py` comme un NOUVEAU champ vérifié
  (`reference_detectee_automatiquement: bool, confiance: float`), sans remplacer la validation
  structurelle existante — additif, pas substitutif (respect du contrat gelé).
- **Outil `controler_qualite_photo`** : OpenCV (Laplacien + histogramme) exécuté systématiquement à
  l'ingestion, AVANT que `qualite_photos.py` ne voie les métadonnées — élimine la possibilité qu'un
  humain déclare un `eclairage` inventé.
- **Politique** : toute sortie de modèle de vision est une `CLAIM UNVERIFIED` au sens PROOF tant
  qu'elle n'a pas traversé une garde déterministe (seuils, cohérence bornes) — jamais un prix
  dérivé directement d'une inférence sans passer par `monte_carlo.py`/`plancher.py`.
- **Skill `generer_devis_pdf`** : gabarit WeasyPrint alimenté uniquement par le contrat gelé
  `EstimationV1` déjà validé — aucun champ libre, pas de prix halluciné dans le gabarit.
- **LLM vision en second avis** : contre-vérifie la classification `niveau_confiance` sans jamais
  la produire seule (double-clé humaine/PROOF : un désaccord CV-déterministe vs LLM-vision déclenche
  `INDETERMINE`, jamais un arbitrage silencieux).

### Agent(s) M4 — Field Ops
- **Outil `optimiser_cedule`** : appel OR-Tools/PyVRP alimenté par une matrice OSRM réelle,
  remplaçant le round-robin — sortie toujours validée par la même structure `{assignations,
  non_cedulees}` déjà contractuelle, pour ne rien casser en aval.
- **Outil `verifier_meteo_creneau`** : appel Open-Meteo avant confirmation d'un créneau ; en cas
  d'alerte, propose automatiquement le motif `meteo` de l'énuméré `reportee` déjà existant — pas de
  nouvel état à inventer.
- **Outil `pointer_terrain`** (déjà largement couvert par `pointage.py`) : ajouter, en amont, un
  appel Traccar SEULEMENT si suivi véhicule demandé — sinon la PWA maison suffit.
- **Politique** : aucune brique météo/routage ne doit jamais écrire dans le registre append-only
  autrement que comme un signal externe horodaté et sourcé — cohérent avec l'interdit existant
  "aucune horloge interne" (CA-M4-15) : ces services FOURNISSENT l'heure/les conditions, jamais le
  système ne les déduit lui-même.

```
docker-compose additions (sidecars, réseau interne uniquement) :
  - sam2-service      (FastAPI + SAM2-small,  CPU, pip: torch-cpu + transformers)
  - osrm              (image officielle Project-OSRM, extrait .osm.pbf Québec)
  - vroom (optionnel) (image officielle, pointe vers osrm:5000)
  - ortools           (PAS de sidecar — dépendance pip directe dans m4_field_ops)

pip additions (dans les modules existants, pas de nouveau service) :
  m3_estimation : opencv-python-headless, weasyprint, (scipy optionnel pour PERT)
  m4_field_ops  : ortools OU pyvrp, httpx (appels OSRM/Open-Meteo)

Économie de tokens : aucune de ces briques ne consomme de tokens LLM — tout est calcul
déterministe ou appel HTTP classique. Seul le "LLM vision en second avis" et
"verifier_meteo_creneau" côté agent consomment des tokens ; les mettre derrière le
routage/cache déjà prévu par l'exigence dure #3 du propriétaire (appel LLM seulement sur
litige de classification, jamais en routine).

Dashboard central : chaque sidecar expose un /health et ses métriques comptent comme des
"modèles/outils connectés" au sens de l'exigence dure #2 — les exposer dans le même écran
que la configuration des fournisseurs LLM.
```
