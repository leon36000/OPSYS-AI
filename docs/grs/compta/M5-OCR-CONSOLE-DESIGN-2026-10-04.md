# Design minimal — revue privée du candidat OCR M5

## Réutilisations présentes

`fusion_pdf_ui.creer_router` est inclus dans `application.creer_application` avec `session_page`, `prefixe`, `cnx_factory` (`application.py:329–334`). `session_page()` exige par défaut une session active et un rôle `nathan_owner` ou `admin`; les rôles sont relus en base à chaque requête, pas crus depuis le cookie signé (`application.py:207–241`). Les handlers utilisent `session_vivante()` avant et après le travail long pour refuser les rôles retirés ou une identité changée (`fusion_pdf_ui.py:394–397,490–517`). Garder ce cycle pour POST et GET candidat.

Les POST HTML contrôlent `sans_query`, whitelist des champs, formulaire borné, puis `securite.csrf_valide` en temps constant; réutiliser `_formulaire_action` ou en faire une variante stricte (`fusion_pdf_ui.py:350–383,519–540`; `securite.py:140–142`). Le formulaire actuel insère un hidden `csrf` échappé. `_reponse()` produit une page privée `Cache-Control: private, no-store, max-age=0`, `Pragma: no-cache`, `nosniff`; le middleware ajoute CSP, DENY frame, no-referrer et no-store par défaut (`fusion_pdf_ui.py:37–44`; `application.py:115–129`). Appels DB/worker vont dans `run_in_threadpool` via `appeler_bloquant` (`fusion_pdf_ui.py:400–409`). Rendre tout champ et token OCR via `pages.e()` (`pages.py:62`), en particulier dans `<pre>`; le candidat est du texte OCR non fiable, jamais HTML/Markdown.

## Interfaces proposées

- Injecter dans le router une configuration serveur `bundle_ocr: Path | None = None`, chargée uniquement depuis la configuration de déploiement administrateur. `None` par défaut signifie bouton absent et POST refusé comme indisponible. Ne jamais lire un chemin bundle dans query, form, JSON, nom de PDF ou cookie; ne pas créer d’UI HTTP pour le modifier. L’administrateur provisionne le bundle validé en montage RO.
- Dans `GET /fusion/pdf/lots/{lot_id}`, afficher une action OCR explicite uniquement si le lot est `REFUSE` avec code `PDF_IMAGE_OU_MIXTE`, que l’opt-in et le bundle sont configurés, et que la révision affichée est courante. Cela réutilise le lien lot existant mais ajoute un formulaire distinct. Ne pas réutiliser le lien AP de `_detail()` (234–235).
- `POST /fusion/pdf/lots/{lot_id}/ocr` accepte exactement `csrf`, `revision_source`, `mutation_id`; refuse query/champs supplémentaires. Revalider lot/code/révision côté métier. Appeler `fusion_pdf_ocr.preparer(cnx_factory, session.utilisateur, lot_id, revision, mutation_id, bundle=bundle_ocr)` dans le threadpool. Le `Path` vient uniquement de la config injectée. Après retour, refaire `session_vivante` et rediriger 303 vers la page de run. L’API métier existe déjà et vérifie identité, UUID, révision, mutation, bundle et réservations (`fusion_pdf_ocr.py:317–329`).
- `GET /fusion/pdf/lots/{lot_id}/ocr/{run_id}` vérifie les deux UUID, appelle `fusion_pdf_ocr.lire()` et s’assure que le run appartient à ce lot avant `lire_resultat()`. Ce dernier ne renvoie que les runs `A_REVOIR` dont source, révision et lot sont toujours liés à un PDF `REFUSE/PDF_IMAGE_OU_MIXTE` (`fusion_pdf_ocr.py:497–525`). Montrer profil/état et tokens comme candidat non vérifié, avec avertissement visible et échappement. Réponse `_reponse()` no-store. Aucun bouton d’acceptation, mapping, écriture AP/comptable, saisie automatique ou export client.

## Fichiers et risques

Implémentation future probablement dans `src/opsys/console/fusion_pdf_ui.py` (ou petit `fusion_pdf_ocr_ui.py` dédié), `application.py` pour l’injection de config et `deploy` pour l’opt-in exclusivement admin. `fusion_pdf_ocr.py` est l’interface métier existante; vérifier séparation lot/run afin qu’un run d’un autre lot ne soit jamais consultable. Risques principaux : texte OCR XSS, IDOR run/lot, CSRF, ancien rôle après calcul, résultat périmé, cache navigateur/proxy, chemin bundle contrôlé par requête, double POST sans `mutation_id`. Le calcul peut continuer après déconnexion (comportement déjà documenté pour la préparation PDF), donc l’UI ne doit pas prétendre l’annuler.

## Tests d’intégration requis

Étendre `tests/test_console_fusion_pdf.py` avec fixtures synthétiques et worker OCR stub au bord métier : admin autorisé / employé, anonyme et rôle retiré refusés; opt-in absent cache action et POST échoue; aucun chemin fourni par HTTP n’est accepté; CSRF, champs dupliqués/inconnus, query et révision obsolète refusés; POST appelle le worker une fois puis 303; reprise idempotente par `mutation_id`; GET autorisé uniquement pour le run lié au lot et résultat `A_REVOIR` encore courant; lots PDF non refusés/image-mixte refusés; GET sans écriture et avec no-store; canari `<script>` rendu en texte; aucune action AP/mapping/export présente. Garder en plus le test r190 du vrai worker dans la qualification séparée d’image/bundle, sans le remplacer par le stub UI.
