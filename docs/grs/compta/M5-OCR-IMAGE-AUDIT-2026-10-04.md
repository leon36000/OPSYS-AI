# Audit ciblé — qualification du worker OCR M5 dans l’image VPS

Périmètre lu : `OPSYS-AI-recent/deploy/Dockerfile`, `core/Dockerfile`, Compose/installateurs, verrous runtime, `src/opsys/ocr_runtime.py`, `ocr_profil.py`, `ocr_worker.py`, `fusion_pdf.py`, et `docs/grs/compta/M5-OCR-WORKER-2026-10-04.md`. Lecture seule; aucun fichier du dépôt/index touché, aucun download, GitHub ou déploiement. Je n’ai pas recherché à nouveau l’artefact r190.

## Conclusion de qualification

Le composant OCR **r190 est qualifié localement seulement** (245/245 cas et un parcours synthétique selon le rapport M5, lignes 3–6 et 49–55). L’image serveur Docker et l’installateur VPS **ne sont pas qualifiés OCR**. Le rapport M5 dit explicitement que l’image, l’installateur, namespaces/cgroups de la cible et provenance complète des dépendances système restent à vérifier (lignes 30–47). L’image produite `opsys:ingestion-pdf-local` n’a même pas été construite/exécutée au diagnostic R48; l’essai Docker hybride sous UID1000/seccomp Moby standard a échoué à créer un namespace (« No permissions to create a new namespace »), et le texte déconseille privileged, SYS_ADMIN ou désactivation seccomp (`docs/ops/INGESTION-PDF-DOCKER.md:10–28,124–138`). Aucun taux de progression n’est déduit.

`deploy/Dockerfile` construit le serveur Python séparé; `core/Dockerfile` construit le Gateway Node/OpenClaw séparé. L’image Core n’est pas l’hôte de ce worker : son runtime est Node 24 Bookworm-slim et son processus est `USER node` (`core/Dockerfile:227–235,249–275,440–445`). Le VPS `deploy/install.sh` compose uniquement `deploy/docker-compose.yml`; il ne sélectionne pas l’overlay OCR/PDF (`deploy/install.sh:28–32`). L’option native différente `install/install.sh --avec-ingestion-pdf` n’est pas une qualification de l’image Docker, et n’installe pas à elle seule Tesseract ou le bundle OCR (`docs/ops/INGESTION-PDF-DOCKER.md:140–154`).

## Ordre minimum d’actions codables avant revendication

1. Choisir la cible effectivement demandée (ici image `opsys` de `deploy/Dockerfile`, pas Gateway Core), puis ajouter une voie OCR explicite, désactivée par défaut, via ARG/overlay Compose et tag d’image distinct. Conserver l’image standard inchangée. L’overlay doit réunir bwrap + extra pypdf + packages OCR sans activer automatiquement un traitement ou un endpoint.
2. Ajouter un verrou OCR reproductible : réutiliser le lock contenant pypdf 6.19.0 et Pillow 12.3.0 (ou régénérer un lock dérivé contrôlé), conserver `--require-hashes`; définir la provenance des paquets OS Tesseract 5.5.0/Leptonica 1.84.1, hash binaire et dépendances système. Un `apt-get install tesseract-ocr` non versionné ne suffit pas.
3. Définir la livraison du bundle PDFium/tessdata par administrateur, en dehors du dépôt et sans téléchargement au démarrage/build. Choisir un chemin stable côté conteneur, montage RO, racine non modifiable, UID/modes conformes au validateur. Faire passer ce chemin uniquement par l’appel opt-in explicite; garder validation de bundle, hashes et refus fermés.
4. Qualifier d’abord `bwrap --unshare-all` dans l’image construite réelle sous UID opsys/1000, avec seccomp/capacités et daemon exactement ceux du VPS visé. Le profil Docker décrit est bloqué; la solution doit être permise et documentée par l’administrateur du daemon/kernel sans privileged, SYS_ADMIN ou seccomp désactivé. Si impossible, maintenir OCR indisponible/refusé.
5. Sur cette image seulement, recueillir manifestes versions/hashes, `id`, `uname -m`, `bwrap --version`, `tesseract --version`+SHA, distribution Pillow/pypdf, hashes bundle, puis exécuter le parcours synthétique qualifié r190 via le worker isolé comme utilisateur non-root. Vérifier refus si bundle/paquet/bwrap absent, et observer mémoire agrégée dans limite cgroup. Ensuite tester l’installateur/daemon VPS; un build local ne vaut pas qualification VPS.

## Commandes locales utiles (préparation, non exécutées)

L’overlay actuellement livré vérifie seulement le socle PDF, donc ces commandes ne qualifient pas OCR. Avec les fichiers secrets locaux déjà préparés par l’opérateur (ne pas imprimer `compose config` sans `--quiet`) :

```bash
docker compose --env-file deploy/.env \
  -f deploy/docker-compose.yml -f deploy/docker-compose.ingestion-pdf.yml config --quiet
docker compose --env-file deploy/.env \
  -f deploy/docker-compose.yml -f deploy/docker-compose.ingestion-pdf.yml build opsys
```

Après ajout de l’overlay OCR, les commandes locales analogues doivent construire le tag OCR sans `up` puis vérifier dans un conteneur jetable sous UID 1000 : `id -u`, `uname -m`, `python -c 'import importlib.metadata as m; print(m.version("Pillow"),m.version("pypdf"))'`, `sha256sum /usr/bin/tesseract`, `/usr/bin/tesseract --version`, et un smoke `bwrap --unshare-all ... /usr/bin/true`. Enfin appeler le worker avec le bundle monté RO et le fixture synthétique r190, vérifier code/empreinte et limites. La smoke bwrap sous le même Docker profile est précisément le test à résoudre, pas une étape à sauter. Ces commandes de qualification n’ont pas été lancées ici.
