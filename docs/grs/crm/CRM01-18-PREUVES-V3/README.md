# M4 → M5 : scénarios V3 fictifs

Ces scénarios sont des sources de QA, pas des preuves d'exploitation ni des tests collectés par défaut. Ils nécessitent une composition isolée contenant M4 `d83a19d4e242297400bdb65c62c331781bd5f2cd` et les commits de la PR M5. Pour les exécuter, copier les fichiers `.py.txt` dans `tests/` en leur donnant un nom `test_*.py`, puis utiliser le harnais privé de la mission. Aucun de ces fichiers ne doit être déposé sur un serveur de production.

- `scenario-v3-partiel.py.txt` traverse les producteurs M3 et M4, deux visites avec pointages V3 typés, l'outil de complétion M4 qui publie le WCT, le bus, la réception et la console M5. Les tarifs et les données sont fictifs. Il vérifie une main-d'œuvre de 730 CAD, l'analyse locale partielle, CSRF, rejeu, collision de rang, révocation tardive, source modifiée après reçu, refus de reçus et preuves corrompus, et confidentialité.
- `scenario-v3-historique.py.txt` ajoute une déclaration et un prix par les outils M6. Les tarifs fictifs mal formés sont refusés, et une équipe au tarif expiré n'est pas chiffrée malgré le tarif valide de l'autre équipe. Une personne fictive partage l'identifiant d'une équipe ; le port M4 atteste le sujet équipe tout en laissant la présence individuelle inconnue. L'analyse historique locale atteint 1 050 CAD de coût et −450 CAD de marge ; elle n'est pas publiée sur le bus. Une révision de tarif rend la trace courante périmée et conserve l'historique. Le dernier événement aval reste partiel.
- `scenario-port-autorite.py.txt` appelle directement le producteur V3 réel sous autorité admin, puis vérifie que les trois transports interdits sont refusés même avec le CAS de la lecture autorisée. Il ne crée pas de port de service.
- `scenario-port-v3.py.txt` utilise le test réel du producteur M4 avec ses deux visites et le registre de tarifs M5. Il complète les contrôles de source périmée et rejeu. Ce scénario publie le WCT par le harnais ; le premier utilise l'outil métier de complétion.

La composition QA de référence avant la tranche de trace historique est `ff88f45dd3150c0f24af26a8840e6322a5bad642`. La tranche supplémentaire a été testée en copie de travail : voir le rapport de PR pour la tête et les résultats exacts. Un test initial a démontré qu'une publication V3 complète peut rester périmée après modification des tarifs ; l'implémentation retenue ne la publie pas. Les sources M4 peuvent encore changer sans notification générale : seuls la lecture admin revalidée et l'historique sont qualifiés. L'outil M5 générique et les consommateurs du bus restent partiels. Les historiques et reçus sont bornés, sans mécanisme d'archivage complet ; les analyses au-delà de la limite d'affichage ne sont pas encore accessibles depuis cette vue.
